# 《餐饮大侦探》游戏设计文档

> 版本：v1.0 | 更新日期：2026年8月 | 状态：MVP开发中

## 一、项目概述

### 1.1 产品定位

《餐饮大侦探》是一款**模拟“创业避坑类直播间”的互动诊断游戏**。玩家扮演一位“侦探主播”，通过与糊涂店主连麦互动，找出餐厅经营中的致命错误，最终给出“及时止损”或“扭亏为盈”的诊断结论。

**Slogan**：*“创业的尽头是负债，负债的尽头是《餐饮大侦探》。”*

### 1.2 产品愿景

让每一位对餐饮创业有幻想的普通人，**在笑声中看清真相，在游戏中学会避坑**。用黑色幽默的方式，传递“创业有风险，入局需谨慎”的核心理念。

### 1.3 目标用户

| 维度         | 描述                                                         |
| :----------- | :----------------------------------------------------------- |
| **年龄**     | 18-40岁                                                      |
| **职业**     | 都市白领、小镇青年、餐饮从业者、创业观望者                   |
| **动机**     | 对餐饮创业好奇、有过失败经历、喜欢看创业避坑类短视频/直播内容 |
| **使用场景** | 碎片化时间（通勤、午休、睡前），单局5-15分钟                 |

## 二、核心玩法设计

### 2.1 游戏流程总览

text

```
┌────────────────────────────────────────────────────────────────┐
│                       关卡选择（15关，3章）                    │
└────────────────────────────────────────────────────────────────┘
                                ↓
┌────────────────────────────────────────────────────────────────┐
│  阶段一：【连麦审问】                                          │
│  · 360°环视抓拍线索（最多3张）                                │
│  · 夺命三连问（租金/流水/人工，从3个选项中选真实数据）          │
│  · 隔壁老王电话验证（获取隐藏线索）                            │
│  · 生成“店主口供 vs 真实数据”对比表                           │
│  · 耐心值5点，归零则诊断失败                                   │
└────────────────────────────────────────────────────────────────┘
                                ↓
┌────────────────────────────────────────────────────────────────┐
│  阶段二：【找茬】                                              │
│  · 在2D餐厅俯视图中找出3-5个致命错误                           │
│  · 每找到一个触发“敲锣”反馈 + 数据面板联动更新                  │
└────────────────────────────────────────────────────────────────┘
                                ↓
┌────────────────────────────────────────────────────────────────┐
│  阶段三：【连线】                                              │
│  · 将“错误原因”与“错误后果”用线配对                           │
│  · Canvas拖拽连线，正确锁定/错误消失并扣耐心值                  │
└────────────────────────────────────────────────────────────────┘
                                ↓
┌────────────────────────────────────────────────────────────────┐
│  阶段四：【急救】                                              │
│  · 从3个方案中选择正确补救措施                                 │
│  · 正确答案往往是“及时转让止损”                                │
└────────────────────────────────────────────────────────────────┘
                                ↓
┌────────────────────────────────────────────────────────────────┐
│  阶段五：【结算】                                              │
│  · 生成诊断报告（得分/亏损/成就称号）                          │
│  · 支持分享裂变                                               │
└────────────────────────────────────────────────────────────────┘
```



### 2.2 核心交互机制

#### 2.2.1 耐心值系统

| 属性         | 说明                                                       |
| :----------- | :--------------------------------------------------------- |
| **初始值**   | 5点（❤️❤️❤️❤️❤️）                                               |
| **扣减规则** | 店主含糊其辞→扣1点；玩家选错数据→扣2点；连线配对错误→扣1点 |
| **归零后果** | 勇哥摔耳机：“下一个！”，游戏直接进入“诊断失败”结算         |
| **视觉反馈** | 扣减时红闪+抖动+音效                                       |

#### 2.2.2 360°环视抓拍

| 属性         | 说明                                        |
| :----------- | :------------------------------------------ |
| **交互方式** | 4-5张静态图轮播，模拟店主拿手机转圈         |
| **核心操作** | 玩家点击“保存线索”按钮收藏关键帧（最多3张） |
| **游戏影响** | 保存的线索会在“找茬”阶段自动高亮对应错误点  |
| **策略深度** | 存错线索会导致找茬阶段信息不足，增加难度    |

#### 2.2.3 店主AI人设

每位店主NPC从以下人设库中抽取，影响回答风格和数据偏差：

| 人设         | 口头禅                   | 数据偏差特征                             |
| :----------- | :----------------------- | :--------------------------------------- |
| **迷糊新手** | “这个……我得问问我老婆。” | 50%问题需追问，耐心值消耗快              |
| **固执老炮** | “我做餐饮二十年了！”     | 拒绝承认错误，数据偏差极大               |
| **甩锅侠**   | “都怪加盟总部！”         | 数据相对准确，但所有问题都怪别人         |
| **网红梦**   | “我在抖音有5000粉丝！”   | 营业额虚报3-5倍，过度自信                |
| **已崩溃**   | “完了完了完了……”         | 数据完全随机，可能在某个点上突然说出真相 |

### 2.3 难度递进设计

| 章节               | 关卡数 | 难度      | 核心主题                       | 新增机制                       |
| :----------------- | :----- | :-------- | :----------------------------- | :----------------------------- |
| **第一章：新手村** | 1-5    | ★~★★      | 基础踩坑（加盟、选址、成本）   | 基础三件套（找茬+连线+急救）   |
| **第二章：进阶篇** | 6-10   | ★★~★★★    | 复合问题（团队、供应链、营销） | 追问机制（选错可重选，扣耐心） |
| **第三章：大佬篇** | 11-15  | ★★★~★★★★★ | 连锁经营、资金链断裂           | 限时机制（每阶段60秒倒计时）   |

## 五、关卡差异化设计

### 5.1 差异化维度

| 维度         | 变化方式                                 | 示例                                       |
| :----------- | :--------------------------------------- | :----------------------------------------- |
| **场景视觉** | 不同店铺类型（奶茶/烘焙/火锅/咖啡/快餐） | 不同配色、不同布局、不同设备               |
| **店主性格** | 5种人设随机/固定搭配                     | 迷糊新手、固执老炮、甩锅侠等               |
| **错误类型** | 7大类错误轮换                            | 租金、选址、成本、竞品、流量、供应链、团队 |
| **数据偏差** | 店主瞎报程度不同                         | 偏差±30%~±300%不等                         |
| **机制组合** | 每5关解锁新机制                          | 追问、限时、多选、隐藏点                   |

### 5.2 错误类型库（7大类，可组合）

| 类型         | 子类                       | 示例                          |
| :----------- | :------------------------- | :---------------------------- |
| **财务类**   | 租金、人工、物料、平台扣点 | 租金5.8万/月 vs 同地段2.5万   |
| **选址类**   | 商圈、位置、周边竞品       | 开在瑞幸+蜜雪中间             |
| **成本类**   | 食材成本、装修、加盟费     | 食材成本率52%（正常≤40%）     |
| **流量类**   | 客流、曝光、转化           | 日均客流20人 vs 盈亏平衡100人 |
| **竞争类**   | 竞品、差异化、价格战       | 定价高于竞品50%               |
| **管理类**   | 团队、排班、培训           | 招不到人，一人顶三个岗        |
| **供应链类** | 进货、库存、物流           | 加盟总部强制高价进货          |

text


### 7.3 数据管理

- **关卡数据**：集中存储在 `levels.js`，新增关卡只需添加JSON对象
- **游戏状态**：`game.js` 管理当前关卡、阶段、耐心值、得分
- **进度持久化**：使用 `localStorage` / `wx.setStorageSync` 保存解锁进度
