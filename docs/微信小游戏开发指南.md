## 0. 技术栈一句话

微信**小游戏**（不是小程序）：没有 WXML/WXSS，全部界面用 **Canvas 2D** 绘制。
入口 `minigame/game.js`，关卡数据在 `minigame/js/data/levels.js`，游戏规则状态机在 `minigame/js/core/state.js`。

| 关键信息 | 值 |
|---|---|
| 项目类型 | 微信小游戏（`compileType: "game"`） |
| AppID | `wx01973db56f70ae3e`（已在 project.config.json） |
| 仓库 | `git@github.com:wang-kx1109/Bust-The-Biz.git` |
| 技术栈 | JavaScript + Canvas 2D（无框架、零构建） |
| 校验 | 3 个 node 脚本（见 §5） |

## 1. 一次性环境准备（每台电脑做一次）

1. **获取权限**：让项目管理员在 [mp.weixin.qq.com](https://mp.weixin.qq.com) →「管理 → 成员管理」把你的微信加为**开发者/体验成员**（真机预览需要）
2. **安装微信开发者工具**：[官方下载](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)，选**稳定版**
3. **登录**：打开工具 → 用你的微信扫码登录

> ⚠️ 别装成 VSCode 插件或"微信开发者工具"的手误版本——真工具有深蓝底微信 logo 图标。

## 2. 克隆 + 导入项目

```bash
git clone git@github.com:wang-kx1109/Bust-The-Biz.git
```

开发者工具里（**不要**直接 VSCode 打开当项目用）：

1. 主界面点 **「+ 导入项目」**（不是新建）
2. **目录**：选 `Bust-The-Biz` 根目录（含 `project.config.json` 的那层）
3. **AppID**：会自动从配置读取 `wx01973db56f70ae3e`，不用手填（不弹输入框是正常的）
4. 确认类型为「**小游戏**」→ 点「确定」

**如何判断导入对了**：左侧文件树应看到 `game.js` / `game.json`（而不是 `app.json`）。

**旧项目残留处理**：如果工具之前打开过本项目旧版本 →「关闭项目」→ 重新导入；还报错就「清缓存 → 全部清除」。

## 3. 编译与验证清单

点顶部 **「编译」** → 左侧模拟器出现游戏。按顺序玩一遍：

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 点「奶茶店」 | 进审问页，店主视频窗晃动，❤️❤️❤️❤️❤️ |
| 2 | 让店主转一圈 → 点 3 张环视卡 | 第 4 张点下去弹"最多收藏 3 条" |
| 3 | 三连问：故意答错第 1 题 | 选项变红 + ❤️ 扣 1 |
| 4 | 答对剩下两题 → 老王电话 | 两行纯文本录音 + 金色揭示 |
| 5 | 找茬点 3 个 ❓ | 敲锣 🔔 动画 + 数据面板红字 |
| 6 | 连线页先左后右 | 绿线锁定；配错 → 红线闪 + ❤️ 扣 |
| 7 | 急救选 C | 弹窗 → 结算页大分/称号/止损 |
| 8 | 面包关重玩 | 找茬**先点「收银台」** → 隐藏"报废率" ❓ 出现 |
| 9 | 故意答错 5 题 | 失败页 💥😤 → 重新诊断 |

**模拟器上的`console`三条ignore**（都不是我们代码的问题）：
- `jsbridge not ready`：启动瞬时噪音（代码已加固兜底）
- `worker path empty`：没注册 worker 的正常提示
- HarmonyOS 升级公告：忽略

## 4. 真机玩 / 发给朋友

**自己手机上玩（预览）**
1. 工具右上角登录的微信 = 有权限的微信（或绑定 AppID 的微信，见 §1.1）
2. 顶部点 **「预览」** → 弹二维码
3. 手机微信「扫一扫」→「打开」→ 游戏在真机跑
4. 无需同一 WiFi；码几分钟过期就重新点预览

**发给朋友（体验版）**
1. 开发者工具点 **「上传」** → 填版本号 → 确定
2. mp.weixin.qq.com →「版本管理」→ 把该版本**设为体验版** → 生成二维码
3. 先确保朋友在「成员管理」里是**体验成员**，才能扫开

**边玩边看日志（真机调试）**
工具栏「真机调试」→ 手机扫码（建议同一 WiFi）→ 手机操作、电脑实时看 console/log。

## 5. 日常开发约定

**改哪儿**
| 想改的 | 文件 |
|---|---|
| 界面/布局/交互 | `minigame/js/scenes/*.js` |
| 游戏规则/得分/解锁/存档 | `minigame/js/core/state.js` |
| 关卡内容（店名/问答/找茬/连线/急救/数值） | `minigame/js/data/levels.js` |
| 画面绘制工具 | `minigame/js/core/gfx.js` |

**每次改完必跑校验**
```bash
node scripts/sanity.js          # 数据完整性/坐标/隐藏点/满分公式
node scripts/sanity-game.js     # 状态机全流程 + 场景接口
node --check <任意.js>          # JS 语法
```

**红线约定**
- **数据双镜像**：`minigame/js/data/levels.js` 与 `miniprogram/data/levels.js` 必须同步修改，sanity 会校验不一致（miniprogram 是遗留存档，平时只需同步数据文件）
- 场景 render() 采用"**测量+绘制+命中同源**"：不要把布局计算和绘制拆成两套函数，否则点击会漂移
- 坐标：逻辑宽 = 750，与关卡数据 1:1；找茬场景坐标直接用数据原值
- Canvas emoji 在 Windows 模拟器可能黑白，**真机为准**——别当 bug 报
- 不提交 `project.private.config.json`（已 gitignore，各电脑私有）

**加新关卡**
1. 给 `minigame/js/data/levels.js` 追加一个关卡对象（参考对照 2 关）：审问(questions)/找茬(zones+faults，750 坐标+可选 unlockBy 隐藏点)/连线(connectPairs)/急救/结算(result)
2. **同步**同样的对象到 `miniprogram/data/levels.js`
3. 跑 `node scripts/sanity.js` 看是否全绿

## 7. 常见问题速查

| 现象 | 原因 | 解法 |
|---|---|---|
| 导入框自动跳「小游戏」 | 正常，AppID 就是小游戏 | 直接确认即可 |
| 报 app.json/game.json 相关错误 | 工具类型识别/残留缓存 | 关闭项目重导 + 清缓存全部清除 |
| 报"自定义编译中指定的启动页面" | 旧自定义编译模式残留 | 编译模式下拉选「普通编译」；详情→本地设置→清空编译模式 |
| 「编译」置灰 | 项目没加载/没登录/基础库下载中 | 确认导入成功；扫码登录；等进度条 |
| `jsbridge not ready` 刷屏 | 基础库过新 + 启动竞态 | 详情→本地设置→调试基础库→切**稳定版**；清缓存重编 |
| 模拟器 emoji 黑白/豆腐块 | Windows canvas emoji 限制 | 真机预览验证，不影响功能 |
| 预览扫码打不开/提示无权限 | 登录微信没被加为成员 | 见 §1.1 成员管理 |
| 手机玩存档丢了 | 换手机/清微信缓存 | 进度存手机本地 wx storage，换设备不迁移（后续可接云存档） |

## 8. 快速上手建议路径

第一次上手 30 分钟走查：
1. 按 §1 装工具 + 登录 → 2. 按 §2 导入 → 3. 按 §3 清单玩一遍 → 4. 按 §4 真机预览一次
